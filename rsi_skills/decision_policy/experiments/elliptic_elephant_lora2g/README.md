# Decision Policy RSI on Elephant-1 LoRA × Elliptic++（2026-11-21/22）

## 起点（所有版本一致）

- 模型：elephant-1 + LoRA（r=32，2 张 A100，1 epoch，5,273 步），按 select NLL 选第 2640 步（0.0667；未训练时 0.747）。
  全参在 2 卡上 OOM，所以用 LoRA；结果不和团队的全参结果放在同一张对比表里。
- 分数：`EL_lora2g_txhist_s0_{val,test}.parquet`（合并后的完整模型，`onejev_score.py`）。
  val 24,225 行：AUPRC 0.913，AUROC 0.981，ECE 0.012。合并模型和 harness 自己的打分在 200 行上平均 |Δp| 0.0008（bf16 数值噪声），NLL 相同。
- 协议：val 的 step 30–32 拟合（11,947 行），step 33–34 比较候选（select，12,278 行，742 个正例）。
  目标 `f1_e2e`，接受规则为按 step 分层的配对 bootstrap 95% CI 下界 > 0。最终评估一律用 test 上的 `f1_e2e`。
- 每个版本跑 3 个副本，只改 `evolve.seed`（自动变异和二次判断的随机种子），提案相同。

### 实验次数与每轮优化

- 4 个版本 × 3 个副本 = **12 次 RSI 运行**；每次 3 轮进化，共 **36 轮**；评估候选策略共 **200 个**（每副本 14–19 个）；被接受 **0 个**。
  另外每版各 1 次 final-test（共 4 次），v4 开发时用 v3 配置做了 1 次复现核对。
- 第 1 轮：我写的提案（3–4 个）加 5–7 个自动变异（8 个里去掉重复的）。第 2、3 轮只有自动变异，因为 incumbent 一直是 baseline，每轮只剩 1–6 个新候选，
  而且越来越多是 no-op（决策与 baseline 完全相同）。
- 每个版本的最好结果几乎都出现在第 1 轮的提案里。第 2、3 轮的自动变异偶尔接近（v2 r0、v3 r0 第 3 轮的“拒判 + 特征二次判断”到 +0.005～+0.0075），
  但 CI 都跨 0。这说明 Skill 流程里“每轮重新诊断、重新写提案”这一步不能省（v1–v4 都只在第 1 轮写了提案，这是这批实验的不足）。

## final-test（预先登记，2026-11-22 02:40，看 test 之前）

每个版本只跑一次，用副本 r0 的配置；baseline 和 incumbent 在全部 val 上重拟合，在 test 上只应用一次。
三个版本的 incumbent 都还是 baseline。为了让 test 有信息量，每个版本再带上它预先选定的领先提案（`--policy`），
并明确标注为“未被接受”：
- v1：`p4_abstain98_logreg`
- v2：`q1_hgb_feat_all`
- v3：`q1_hgb_feat_all_bag5`

结果（2026-11-22 07:30 运行；test 97,756 行，step 35–49；每版耗时 14–24 秒）：

| 策略 | test f1_e2e | precision | recall | pre43 F1 | post43 F1 | 相对 baseline 的收益 [95% CI] |
|---|---|---|---|---|---|---|
| baseline = 三个版本的 incumbent | **0.6102** | 0.6654 | 0.5634 | 0.7250 | 0.4262 | — |
| v1 领先提案 p4_abstain98_logreg（未接受） | 0.5751 | 0.5657 | 0.5849 | 0.6834 | 0.4048 | −0.0351 [−0.0396, −0.0308] |
| v2 领先提案 q1_hgb_feat_all（未接受） | 0.5871 | 0.5874 | 0.5869 | 0.7018 | 0.4051 | −0.0230 [−0.0292, −0.0168] |
| v3 领先提案 q1_hgb_feat_all_bag5（未接受） | **0.6187** | 0.6676 | 0.5765 | 0.7454 | 0.4187 | **+0.0086 [+0.0021, +0.0145]** |

读法：
- test 上整体 F1 只有 0.61（val select 上是 0.93），test 的 AUPRC 0.620、AUROC 0.878（val 是 0.913、0.981）。主要掉在 step 43 之后（post43 F1 0.43），
  这是 Elliptic 已知的分布突变（暗网市场关停）。策略层能做的有限，主要是模型的问题。
- 接受规则起了作用：v1 和 v2 的领先提案在 val 上看起来不差（+0.0002、+0.006），但在 test 上都明显变差（−0.035、−0.023），规则正确地拒绝了它们。
- v3 的 5 种子平均让带特征的二次判断变得稳健：在 test 上是唯一显著为正的策略（+0.0086，CI 不跨 0），提升集中在 pre43（+0.020），post43 略降（−0.008）。
  它在 val 上没被接受，是因为 select 只有 2 个 step、CI 太宽，不是因为它无效。
- 下一步可以做：用 val 的全部 5 个 step 做按 step 的交叉验证来比较候选（拉长 select、收窄 CI）；针对 post43 的漂移试滚动重拟合加特征二次判断；把 39 个自信漏判交给训练/数据负责人。

## v4：按 step 的时间外交叉验证（2026-11-22 07:40）

**改了什么**：新增 `protocol: {by: step_cv, cv_steps: 3}`。val 的 step 32、33、34 各用只在更早 step 上拟合的策略打分，三个 fold 合起来比较候选。
select 从 2 个 step（12,278 行）增加到 3 个 step（18,000+ 行），而且每个 fold 都遵守“用过去拟合、用在未来”。原有协议的代码路径不变：
用 v3 r0 的配置重跑了一遍，17 条 archive 记录（hash 和 objective）和原来完全一致，v3 的代码快照在 `history/v3/`。

**为什么**：v3 的领先提案在 val 上没被接受、在 test 上却显著为正；v2 的领先提案在 val 上不错、在 test 上却变差。说明只看 2 个 step 的 select 判断不了一个策略在分布变化下是否稳健。

**结果**（3 个副本，每副本 82–121 秒，baseline 的 CV F1 = 0.9068）：

| 提案 | r0 | r1 | r2 | 平均收益 | step 32 / 33 / 34 的 F1（r0） |
|---|---|---|---|---|---|
| baseline | 0.9068 | 0.9068 | 0.9068 | — | 0.887 / 0.898 / 0.944 |
| q1_hgb_feat_all_bag5（v3 的领先提案） | 0.8418 | 0.8455 | 0.8441 | −0.063 | **0.765** / 0.910 / 0.944 |
| q2_abstain90_hgb_feat_bag5 | 0.9103 | 0.9076 | 0.9077 | +0.0017 | 0.887 / 0.911 / 0.947 |
| r1_rolling_hgb_feat_bag5 | 与 q1 相同（单 step 的 fold 里滚动重拟合等于静态拟合） | | | | |

读法：v4 暴露了 q1 的脆弱：当二次判断只能在 2 个 step（30–31）上训练时，它在 step 32 上把 F1 从 0.887 拉到 0.765。
这和它在 test 上 post43 变差的现象一致。只重判拒判带的 q2 在三个 step 上都不低于 baseline，是更稳健的方向，但收益小、CI 跨 0，仍未被接受。

**final-test 预先登记（07:45，看 test 之前）**：v4 r0，incumbent（仍是 baseline）加领先提案 `q2_abstain90_hgb_feat_bag5`（未被接受）。

**final-test 结果**：baseline 0.6102；q2_abstain90_hgb_feat_bag5 为 0.5972，收益 −0.0130 [−0.0190, −0.0072]（pre43 0.7242 ≈ baseline，post43 0.3998 对比 0.4262）。

**四个版本合起来看**：val 的 5 个 step（30–34）全在 step 43 之前，而 test 的损失主要来自 43 之后的分布突变。
val 上的任何比较方式（2 个 step 的 select，或 3 个 fold 的时间外 CV）都看不到这种突变，所以挑出来的领先提案在 test 上时好时坏：
v3 的 q1 +0.009，v2 的 q1 −0.023，v4 的 q2 −0.013。保守的接受规则（CI 下界 > 0）四个版本都没有接受任何候选，test 上始终保住了 baseline 的 0.610，
这本身是对的。要在 test 上稳定超过 baseline，需要能应对 43 之后突变的策略（例如在部署时用延迟到达的标签滚动重拟合），以及能模拟这种突变的评估方式。

- 候选越多，val 上的最好成绩越偏乐观（v5 每次运行 69–125 个候选），所以 final-test 才是判断依据。

**v5 final-test 预先登记（15:35，看 test 之前；按“每个版本各一次 final-test”的批准）**：`configs/long/v5_it20_r0.yaml`，incumbent（仍是 baseline）
加 r0 的领先候选 `final_test_policies_v5_lead.yaml`（拒判 10% + 带特征的 hgb 二次判断（9 种子平均），并在部署时用延迟 1 步的标签滚动重拟合；未被接受）。

**v5 final-test 结果**（test 97,756 行）：

| 策略 | f1_e2e | precision | recall | pre43 F1 | post43 F1 | 相对 baseline [95% CI] |
|---|---|---|---|---|---|---|
| baseline = incumbent | 0.6102 | 0.6654 | 0.5634 | 0.7250 | 0.4262 | — |

读法：
- 这是目前所有版本里 test 上最大的提升，pre43 和 post43 两段都显著变好（+0.064、+0.068），precision 从 0.67 提到 0.81。
- **要注意它多用了信息**：这个策略是 rolling 重拟合，在 test 上第 t 步之前，用到了第 t−1 步及更早的真实标签（标签晚 1 步到达），这模拟的是部署时有标签陆续回流。

- 在 val（step_cv）上它只有 +0.0055 且 CI 跨 0，因为 val 的 5 个 step 里没有分布突变，滚动的好处体现不出来；到了有突变的 test 上才显出来。这也说明需要一个能模拟突变的评估协议，才能让接受规则在 val 上就把它选出来。

## v6：部署一致的协议 + 跨 seed 共识（2026-11-22 17:20）

**改了什么**：`protocol: {by: step, select_last: k}`（静态策略只在前面的 step 上拟合一次，滚动策略用晚 1 步的标签，和 final-test 的做法一致）；
`by: step_cv` 时 `check` 和报告里给出警告；新命令 `dpolicy consensus`：同一设定的多个 seed 中，过半通过接受规则的候选才算共识选择。

**为什么**：只用 val 的拆解实验（`ablation_v5lead/RESULTS.txt`）显示，v4 的 step_cv 让每个策略都按 fold 重新拟合，相当于静态 baseline 也在“滚动”，
于是滚动策略的价值完全被抵消（滚动单独的收益恰好是 0）；在 select=33–34 的协议下，v5 领先策略（拒判 + 特征二次判断 + 滚动）3 个 seed 中有 2 个通过接受规则。

**结果**（v5 的搜索设置，10 轮，3 个 seed，提案沿用 v4 的 4 个）：

| 设置 | 被接受 | 接受的策略 | 共识（过半 seed 通过） |
|---|---|---|---|
| select = 最后 2 个 step（33–34） | **3 个 seed 都有** | r1、r2：`r1_rolling_hgb_feat_bag5`（+0.0111 [+0.0012, +0.0202]、+0.0091 [+0.0008, +0.0178]）；r0：拒判 20% + recall≥0.7 规则 + 特征 hgb（+0.0106 [+0.0017, +0.0192]，第 6 轮） | `r1_rolling_hgb_feat_bag5`（2/3） |
| select = 最后 3 个 step（32–34） | 0 | — | 无（最好 +0.0040） |

这是 RSI 第一次在 val 上自己选出并替换了 incumbent。需要如实说明两点：
- `r1_rolling_hgb_feat_bag5` 是 v4 时写的提案，写的时候已经看过 v3 的 test 结果（“step 43 之后变差”），所以这个**方向**受过 test 的启发；但是否接受完全由 val 决定。
- select=32–34 时没有接受：fit 只剩 30–31 两个 step，二次判断训练行太少（和 v4 里 step 32 崩掉的现象一致）。

**v6 final-test 预先登记（17:40，看 test 之前；按“每个版本各一次”的批准）**：`configs/long/v6_k2_r1.yaml`，incumbent = 共识选择 `r1_rolling_hgb_feat_bag5`，
另加 r0 的 incumbent（`final_test_policies_v6_r0_incumbent.yaml`）作为对照。

**v6 final-test 结果**（test 97,756 行）：

| 策略 | f1_e2e | precision | recall | pre43 F1 | post43 F1 | 相对 baseline [95% CI] |
|---|---|---|---|---|---|---|
| baseline | 0.6102 | 0.6654 | 0.5634 | 0.7250 | 0.4262 | — |
| **incumbent = 共识选择 `r1_rolling_hgb_feat_bag5`（RSI 在 val 上接受）** | **0.7014** | 0.7843 | 0.6343 | 0.7914 | **0.5685** | **+0.0912 [+0.0829, +0.0997]** |
| r0 的 incumbent（静态：拒判 20% + recall≥0.7 + 特征 hgb） | 0.6433 | 0.7413 | 0.5682 | 0.7653 | 0.4435 | +0.0331 [+0.0269, +0.0393] |

读法：
- 这是第一次由 RSI 自己在 val 上接受、再在 test 上验证的结果：F1 从 0.610 到 0.701，post43（分布突变之后）从 0.426 到 0.569。
- 共识选择是**滚动**策略：在 test 上，第 t 步用到了 t−1 步及以前的真实标签（晚 1 步到达），模拟部署时标签陆续回流；baseline 是静态的。
  所以它和静态 baseline 的差包含了“延迟标签反馈”的价值，最公平的对照是团队的滚动方法（滚动重校准、滚动训练）。
- 不用 test 标签的静态 incumbent（r0）也显著提升了 +0.033，这部分完全来自策略层（拒判带 + 特征二次判断）。
